# 问题

为什么 MySQL 常用 B+ 树做索引，什么查询用不上索引？

# 30秒回答

B+ 树矮、叶子有序且用链表相连，适合范围查询和磁盘页读取。联合索引遵守最左前缀。对列做函数、前置模糊匹配、或者优化器判断回表太贵时，索引可能用不上。

# 深入理解

InnoDB 主键是聚簇索引，叶子存整行。二级索引叶子存主键，查非索引列要回表。覆盖索引让查询只打二级索引。`EXPLAIN` 看 `type`、`key`、`rows`、`Extra`。范围条件后面的联合索引列通常无法继续用。

低选择性列单独建索引收益小。写多的表索引不是越多越好，每次写入都要维护索引。

# 面试追问

## 为什么不用哈希索引做主键？

哈希不支持范围和排序，冲突后还要拉链。B+ 树同时覆盖点查和范围。

## 回表是什么？

二级索引只拿到主键，再去聚簇索引取整行。需要的列都在索引里就可以避免。
