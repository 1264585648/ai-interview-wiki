# 问题

怎么判断一次提示修改是变好了，而不是刚好这几个例子好看？

# 30秒回答

先固定模型和任务，准备一份带标签的小评测集，覆盖正确、拒答、边界和已知失败。每次只改提示的一块，比通过率、格式错误率和越权率。离线过了再灰度。没有对照，提示迭代没有结论。

# 深入理解

评测集要像线上，而不是像你希望的线上。至少分开看：任务是否做对、格式是否可解析、该拒的是否拒了、有没有被注入带偏。一个总分会掩盖“准确率涨了但拒答崩了”。

改提示时保留版本和触发原因。线上抽检失败要回放到评测集，否则下周会修回去。示例、系统规则、输出 schema 的改动不要捆在一次发布里。

人也要抽看。自动分只能抓住可判定的错误，语气、隐瞒和牵强引用仍要人看。

# 面试追问

## 评测集要多大？

先覆盖每类关键失败十几条，能对比就行。比规模更重要的是失败类型齐，以及和线上分布不像两套题。

## 线上变差怎么回滚？

提示和模型版本一起记录。指标掉了先回到上一版提示，再查是数据变了还是提示改坏了。

# 真实面经

常见问法：提示改了三次，你怎么证明第三次更好；你会看哪些指标。
