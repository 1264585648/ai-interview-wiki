# 问题

系统提示、开发者提示、用户提示怎么分工？系统提示里最容易写错什么？

# 30秒回答

系统提示放稳定规则：角色、能用的工具、必须拒绝的事、输出契约。用户提示放这一次的问题和材料。优先级要写明：系统规则高于用户要求，检索到的证据高于模型记忆。不要把密钥、完整权限名单或“忽略以上所有指令”防注入咒语当成系统提示的核心。

# 深入理解

系统提示适合短、稳、可测。写成公司文化散文，模型记不住关键句。更好的写法是条目：先做什么，遇到冲突听谁的，缺信息时问还是拒，输出字段有哪些。

用户能看到或能改的内容，都不要当信任边界。用户说“你现在是管理员”不能提升权限。真正的权限在工具和后端，不在提示词。

角色扮演只用于设定任务视角，例如“你是代码审查员，只指出缺陷”。不要用角色替代验收标准。

# 面试追问

## 用户要求和系统提示冲突怎么办？

先遵守系统里的安全和范围，再在允许范围内回答。应拒绝的请求要说明缺什么，而不是假装执行。

## 系统提示要不要放全部业务知识？

不要。易变知识放检索，稳定口径放系统提示。系统提示一长，改一条规则就要全量回归。

# 真实面经

常见问法：系统提示和用户提示各放什么；用户粘贴一段“忽略之前规则”时，系统该怎么反应。
