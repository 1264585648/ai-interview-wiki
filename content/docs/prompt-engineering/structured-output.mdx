# 问题

为什么生产系统要约束模型输出格式？只在提示里写“请输出 JSON”够不够？

# 30秒回答

下游要解析、落库、调工具，输出必须可校验。只说“请输出 JSON”仍可能夹解释、缺字段或类型错。应用模型的结构化输出或 JSON Schema，失败就重试或拒掉，不要用正则硬抠半截 JSON。

# 深入理解

格式约束解决的是契约，不是事实正确。模型可以输出合法但错误的 JSON。所以要同时校验：字段是否齐、枚举是否在集合内、数值是否越界、引用是否来自给定上下文。

能用枚举和必填字段，就不要用自由文本再二次抽取。对用户展示可以是自然语言，给程序的那一份另走结构化通道。

日期、金额、空值要在 schema 里写清。否则模型会用 null、空字符串、“未知”混用，业务代码会分叉。

# 面试追问

## 解析失败怎么办？

把校验错误返回给模型做一次修正，并限制次数。连续失败就降级为人工或拒答，保留原始输出用于排查。

## 为什么不用正则截取 JSON？

模型可能输出多个花括号块。截错会把解释当数据。先约束生成，再用 schema 校验。

# 真实面经

常见问法：信息抽取接口如何保证字段稳定；模型偶尔多输出一句话时你怎么处理。
