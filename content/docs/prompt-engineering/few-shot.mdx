# 问题

Zero-shot、Few-shot、思维链分别解决什么问题？例子怎么选才不会帮倒忙？

# 30秒回答

Zero-shot 只给任务和约束，适合规则已经写清楚的简单任务。Few-shot 给少量输入输出样例，用来对齐口径和格式。思维链让模型先写中间步骤再给答案，适合需要推理的题，但会计费、变慢，也可能把推理过程暴露给用户。

# 深入理解

例子不是越多越好。每个例子都要覆盖一种真实失败：边界输入、拒答、缺字段、格式例外。例子互相矛盾，模型会学到不稳定口径。

思维链有两种用法。对用户可见时，只在解释有价值时打开。对内部链路，可以只要中间结构、对用户只返回最终字段。现在很多模型支持单独的推理开关，不要和业务输出混在一个字段里。

面试加分点：Few-shot 解决的是分布对齐，不是注入新知识。模型没见过的事实，仍要靠检索或工具，而不是多贴几个例子。

# 面试追问

## 例子从哪来？

从线上失败和人工纠错里抽，不要编理想样例。覆盖高频和最贵的错误各几个即可。

## 思维链一定会更准吗？

不会。简单分类加思维链可能更慢且更飘。先用评测对比打开和关闭，再决定。

# 真实面经

常见问法：给一个分类或抽取任务，追问你为什么给三个例子，以及例子冲突时怎么办。
