# 问题

提示词工程到底在优化什么？为什么不能只说“把提示写好一点”？

# 30秒回答

提示是给模型的任务接口：要做什么、看哪些输入、不能做什么、输出长什么样。提示词工程优化的是这个接口的稳定性，不是堆形容词。先固定任务和评测，再改提示；提示救不了的，才考虑换模型或微调。

# 深入理解

一次可用的提示通常包含四块：任务、上下文、约束、输出格式。缺任务，模型会自由发挥；缺约束，安全和质量边界不清楚；缺格式，下游解析会碎。

面试里要能区分三层：

- 提示能修的：格式、口径、忽略无关信息、按步骤做简单推理。
- 提示修不好的：模型没有的知识、需要稳定计算的逻辑、必须可审计的业务规则。
- 不该用提示硬扛的：把系统提示当成权限系统，或指望一段话挡住提示词注入。

好的回答会补一句：提示要和评测一起改。没有失败样例，提示迭代就是感觉。

# 面试追问

## 提示词和微调怎么选？

格式、口径、少量示例，先改提示。同类错误大量出现、必须稳定记住业务术语或风格，再考虑微调或专门模型。微调也替代不了检索和工具。

## 提示越长越好吗？

不是。长提示更贵、更慢，关键约束还会被稀释。只放当前任务需要的规则和证据。

# 真实面经

常见问法：让你设计一个客服或抽取接口，先问你会把哪些东西写进提示，哪些不写。
