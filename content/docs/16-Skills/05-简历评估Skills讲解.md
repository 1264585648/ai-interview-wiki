# ✅简历评估Skills讲解

上一节我们使用Qoder开发了一个简历评估的Skill，只有一个SKILL.md就能实现了简历评估，看上去很神奇，这是因为很多事情Qoder都帮你干了。

这里说的很多事指的是简历评估任务执行过程中的事儿，并不是开发SKILL过程的事儿：

1、简历下载

2、jd.md文档读取

3、PDF简历读取

4、简历评估

我们再看看那个Skill，你会发现，其实他里面有几个地方需要注意：

```
1. 使用 Read 工具读取项目根目录下的 `jd.md` 文件，获取岗位要求
2. 使用 Read 工具读取用户提供的简历 PDF 文件（Read 工具支持读取 PDF）
3. 如果用户未提供简历路径，使用 AskUserQuestion 询问简历文件路径
```

这里面的Read工具、AskUserQuestion，都是啥？

其实这些就是工具，Read是Qoder内置的工具，AskUserQuestion是需要我们单独提供的工具，如果没提供，Qoder可能会通过python写一个工具出来供我们调用。

所以说，Skills它并不是工具，他只是一份工具使用的说明书，他把提示词、工作流程（如何调用工具、什么时候调用工具、遇到问题怎么办）这些给封装到一起了。

实际上Agent（Qoder）在运行的时候，会参考Skill中定义的指令来调用具体的工作干活。

所以，如果你直接把这个Skill拿到Claude Coder，或者你自定义的Agent中，可能就会无法正常执行，因为这些工具他们不一定有。

还有一个值得注意的地方是，在SKILL.md中：

```
- 岗位JD文件固定存放在项目根目录的 `jd.md` 文件中

1. 使用 Read 工具读取项目根目录下的 `jd.md` 文件，获取岗位要求
```

都是说要从项目的根目录读取jd.md，但是实际上我们在别的Agent中集成这个Skill的时候，是不一定要把这些文件放到项目的根目录的，所以，这块可能需要修改，可以改成相对目录，建议的方案是用markdown语法做关联如：

```text
- 岗位JD文件固定存放在项目根目录的 [jd.md](jd.md) 文件中
```

或者，让他作为references，一起放到skill下，可以和你的qoder继续对话，让他帮你做修改即可：

请你把jd.md作为skill的一部分，作为references，即可参考的示例文件。

以上，就是我们这个简历评估Skill中需要关注的内容，这个Skill我们后面还会把他集成到我们自己开发的Agent中，那时候还会基于上面的这些内容做调整。
