# ✅L1/L2意图识别针对多意图的支持

在我们最开始的方案设计中，我们的L1-L2-L3三层意图识别中， L1/L2 是单意图短路机制，也就是说他们只会优先匹配到一个意图，这就会导致复杂句子本来可能是多意图，但是存在被提前识别成单意图的风险。

为了解决这个问题，我们针对L1/L2做了一些改造。

这次改造的commit记录在这里：

[https://codeup.aliyun.com/67c56af4e77e9167fa2fa6df/LLMentor/commit/8850d9831f327c0f6e4b9240df275d837b028e5c?branch=master](https://codeup.aliyun.com/67c56af4e77e9167fa2fa6df/LLMentor/commit/8850d9831f327c0f6e4b9240df275d837b028e5c?branch=master)

**但是需要注意的是，gogo-agent 的前三层（L0 结构启发、L1 规则、L2 向量）从不产出"多意图"结果——它们能做的，只有在发现可能有多意图时主动弃权、把整句交给 L3 大模型。** 真正判定 multi_intent=true、并把多个意图拆成有序数组的，只有 L3。

L3 是唯一能"把多个意图都识别出来、按依赖排序、标 multi_intent=true"的层（它的系统提示词明确要求这么做）。前三层为多意图识别做的所有事情，本质就是**三道形态各异、但目标一致的"多意图守卫"**：宁可多走一次 L3 慢路径，也不把复合句压扁成单意图。

L0

L0 是最外层、最粗的一道筛子，位于 IntentRecognitionRouter.route() 的最前面。它不看语义、只看**句子结构**：如果一句话"够长 + 含并列/顺承连词 + 连词不在句首"，就判它疑似多意图复合句，**连 L1/L2 都不试，直接交 L3**。

L0 守卫的精髓在于**误判代价极低**：万一把一个单意图长句误判成多意图，唯一后果只是多走一次 L3，绝不会路由到错误的子智能体。所以它可以放心地"宁可错杀"。

L1

L1 规则匹配器为多意图做的事更精细。它的 evaluate()**不是"首中即返"，而是两步走**——先做多意图守卫，通过了再做单意图优先级匹配。

守卫命中后返回的 AMBIGUOUS 裁决，在 route() 里被特殊处理——**连 L2 都一起跳过，**因为 L2 向量匹配结构上**同样只产出单意图**，让它去匹配一个已知的多意图复合句，只会重复 L1 的错误——把复合句压成单意图。所以 L1 一旦判歧义，L2 就没有再试的价值，直接交 L3。

L2

如果句子躲过了 L0（不含强连词或太短）、也没被 L1 判歧义（比如说法非模板、L1 压根没命中），落到 L2 向量层，这里还有第三道守卫——**歧义 margin**。

L2 检索 top-2，当 top-1 和 top-2 **属于不同意图、且相似度分差小于 0.05** 时，说明这句话的向量同时贴近两个意图的种子样本（复合句的典型表现），L2 主动弃权。

这道守卫和 L1 的思路一脉相承，只是判据从"子句类别分散度"换成了"向量相似度的接近度"：**主意图不够突出（和第二意图咬得太紧），就不敢认单意图，交 L3。**

至此，三道守卫凑齐，形态各异但判据同源：

| 层 | 守卫形态 | 判据 | 触发后动作 |
| --- | --- | --- | --- |
| L0 | 结构启发 | 长句 + 强连词 + 连词位置 ≥ 4 | 跳过 L1/L2，直接 L3 |
| L1 | 子句级类别分散度 | 子句命中类别横跨 ≥ 2 个子智能体（寒暄除外） | 判 AMBIGUOUS，跳过 L2，交 L3 |
| L2 | 向量歧义 margin | top-1/top-2 意图不同且分差 &lt; 0.05 | 弃权，交 L3 |
