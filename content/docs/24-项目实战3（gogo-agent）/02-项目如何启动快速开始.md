# ✅项目如何启动&快速开始

配置修改

找到项目中的application.yml，搜索`# 记得改成你自己的` 这句话，他前面的配置你需要改成你自己的。

| 用途 | 配置项 | 获取方式 | 是否必改 |
| --- | --- | --- | --- |
| **DashScope API Key** | `agentscope.dashscope.api-key` | [aliyun.com/product/bailian](https://www.aliyun.com/product/bailian)<br>(注意：代码中默认用的qwen3.7-max，费用较高，注意成本呢） | 是 |
| MySQL | `spring.datasource.url`<br>`spring.datasource.username`<br>`spring.datasource.password` | 自己部署或者用云服务 | 是 |
| Redis | `spring.data.redis.host`<br>`spring.data.redis.password`<br>`spring.data.redis.username` | 自己部署或者用云服务 | 是 |
| **百炼记忆库（长期记忆）** | `agentscope.bailian.*`<br>（access-key-id / access-key-secret / workspace-id / index-id） | 百炼控制台创建 | 不提供无法查询用户偏好 |
| **百炼景点查询知识库（RAG)** | `agentscope.bailian.memory-library-id` | 百炼控制台创建 | 不提供无法查询城市有哪些景点 |
| **NewsData.io API Key**<br>查询目的地新闻资讯 | `app.news-api-key` | [https://newsdata.io](https://newsdata.io) | 不提供无法查询城市有哪些新闻 |
| **weather MCP Endpoint**<br>天气 MCP（阿里云网关） | `app.weather-mcp.endpoint ` | [https://market.aliyun.com/detail/cmapi00074002#sku=yuncode6800200004](https://market.aliyun.com/detail/cmapi00074002#sku=yuncode6800200004) | 不提供无法查询城市天气 |
| **Orizn Visa API Key**<br>签证 MCP | `app.orizn-mcp.api-key` | [https://visa.orizn.app](https://visa.orizn.app) | 不提供无法查询签证信息 |

初始化数据库

建库

```sql
CREATE DATABASE gogo_travel DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

执行 DDL 与初始化数据

在 MySQL 中执行代码中的SQL：`src/main/resources/db/schema.sql`

脚本会创建 11 张表并写入：

- 5 个测试用户档案 `user_profile`（`u_001` / `u001` / `u002` / `u003` / `u004`）
- 5 个登录账号 `user_account`（明文密码 `123456`，仅用于本地开发）
- 12 条差旅政策 `travel_policy_rule`（4 职级 × 3 城市等级）

| 账号 | 密码 | 姓名 | 角色 |

启动后端

方式 A：IntelliJ IDEA（推荐）

1. 打开项目根目录，等 Maven 索引完成
2. Project Structure → SDK 选 **JDK 21**
3. 右键 GogoTravelApplication.java → **Run 'GogoTravelApplication'**

看到以下日志代表启动成功：

```text
Started GogoTravelApplication in x.xxx seconds
Tomcat started on port 8080 (http)
```

查看日志（强烈建议改成DEBUG）

代码中我打了很多用于调试的日志，方便你了解agent的运行流程。但是需要你把日志级别改成DEBUG才行，默认使用INFO：

```text
logging:
  level:
    com.gogo.travel: DEBUG
```

方式 B：命令行 Maven

```bash

cd /path/to/gogo-agent

# 首次或依赖有变更
mvn -DskipTests clean install

# 启动（会阻塞在前台，Ctrl+C 停止）
mvn spring-boot:run
```

看到以下日志代表启动成功：

```text
Started GogoTravelApplication in x.xxx seconds
Tomcat started on port 8080 (http)
```

方式 C：可运行 Jar

```bash

mvn -DskipTests clean package

# 生成 target/gogo-agent-1.0.0-SNAPSHOT.jar
java -jar target/gogo-agent-1.0.0-SNAPSHOT.jar
```

生产/Docker 场景推荐这种方式，配合 `-D` 或环境变量覆盖配置。

启动前端

安装依赖

```bash
cd frontend
npm install     # 首次或 package.json 变更后运行
```

配置后端地址（可选）

前端默认走 `http://localhost:8080`（见 [src/api/auth.ts](http://localhost:63342/markdownPreview/94912733/markdown-preview-index-798872021.html?_ijt=a2ln8e432hchgtgvd6r8t5jdam#) 等）。如果后端跑在别的地址，创建 `frontend/.env.local`：

```bash

VITE_API_BASE=http://192.168.1.100:8080
```

启动开发服务器

```bash
npm run dev
```

看到：

```text
VITE v8.x  ready in xxx ms
➜  Local:   http://localhost:5173/
```

浏览器打开 `http://localhost:5173`，进入登录页。

生产构建

```bash
npm run build     # 产物在 frontend/dist
npm run preview   # 本地预览生产包
```

第一次跑通

按以下顺序验证核心链路：

Step 1 — 登录

- 浏览器打开 `http://localhost:5173`
- 输入 `alice` / `123456` 登录 → 进入主对话页

Step 2 — 发起对话

输入几个逐层验证的问题：

| 输入 | 期望结果 | 验证点 |
| --- | --- | --- |
| `你好` | 短回复 + 推荐问题 | 基础 LLM 通路 |
| `我明天从北京去上海出差 3 天，帮我看下政策` | InfoAgent + PolicyTools 联合回答 | RAG + 政策工具 |
| `我要请假出差，帮我建个差旅单` | Human-in-the-Loop 表单弹出 | `UserInteractionTools` |

Step 3 — 观察 SSE 事件

- 打开浏览器 DevTools → Network → 筛选 `respond`
- 会看到 `text/event-stream` 连接持续接收：`thinking` / `progress` / `travel_data` / `message` / `suggestions` / `done`

Step 4 — 验证会话持久化

- 在左侧 `Sidebar` 看到会话已保存，标题由 `ConversationTitleService` 异步生成
- 刷新页面重新登录 → 点开历史会话 → 消息列表完整回显

Step 5 — 后台数据核对

```sql

USE gogo_travel;
SELECT conversation_id, title, updated_at FROM chat_conversation ORDER BY updated_at DESC LIMIT 5;
SELECT message_id, role, LEFT(content, 60) AS preview FROM chat_message ORDER BY created_at DESC LIMIT 10;
SELECT * FROM agentscope_session LIMIT 3;
```

看到上述表有数据即说明多轮记忆与会话历史都已落库。

常见问题（FAQ / 故障排查）

后端启动失败

| 现象 | 排查 |
| --- | --- |
| `Public Key Retrieval is not allowed` | JDBC URL 加`allowPublicKeyRetrieval=true` |
| `Communications link failure` | MySQL 未起 / 网络不通 / 密码错 |
| Redis 连接超时 | `REDIS_HOST/PORT/PASSWORD`未按环境覆盖 |
| `Unknown initial character set index '255'` | MySQL &lt; 8.0，建议升级 |
| DashScope 401 / 403 | `DASHSCOPE_API_KEY`未生效，检查环境变量顺序 |
| `orizn-visa-mcp`<br>启动失败 | `npx`不在 PATH，或首次拉包超时；把<br>`ORIZN_MCP_COMMAND`改为`npx`绝对路径 |
| 端口 8080 被占 | `export SERVER_PORT=8081`<br>（或改`server.port`） |

前端相关

| 现象 | 排查 |
| --- | --- |
| 登录报网络错误 | 检查后端是否已跑起来 +`VITE_API_BASE`指向正确地址 |
| SSE 只收到几条就停 | 反向代理未关闭 buffering；开发环境直连 Vite 不受此影响 |
| 401 Unauthorized | Token 过期或未在请求头带`Authorization` |
| `npm install`<br>慢/失败 | 切换国内镜像：`npm config set registry https://registry.npmmirror.com` |

对话相关

| 现象 | 排查 |
| --- | --- |
| 回复很慢 / 一直转圈 | 观察后端`AgentExecutionLoggerHook`日志，看是哪一步慢；可能是 MCP 拉子进程首次冷启动 |
| 搜索卡片不显示 | 对应 Skill CLI 未安装（如`tuniu-cli`<br>），查看后端日志中的 stderr |
| Agent 中断不生效 | Redis 未连通，`AgentInterruptBroadcast`无法广播 |
| 熔断误伤 | 调`app.circuit-breaker.failure-threshold`与冷却时间，或临时`TOOL_CB_ENABLED=false` |
