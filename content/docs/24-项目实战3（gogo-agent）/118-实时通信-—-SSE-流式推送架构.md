# 实时通信 — SSE 流式推送架构

**Server-Sent Events（SSE）** 是 HTML5 规范中定义的一种**服务器向客户端单向推送**的通信协议。它基于标准 HTTP 长连接，服务器可以在一个持久的 HTTP 响应中持续向客户端发送文本数据流，而无需客户端反复轮询。

与 WebSocket 的双向通信不同，SSE 天然适合"服务器 → 客户端"的单向数据推送场景，例如：

- AI 对话的流式输出（逐 token 推送）
- 实时进度通知
- 事件驱动的状态推送

SSE 的响应 Content-Type 为 `text/event-stream`，数据格式为纯文本，每条消息由若干字段组成，以**空行**分隔：

```text

event: message
data: {"text": "你好"}

event: progress
data: {"type": "tool_call", "message": "查询天气"}
```

| 字段 | 说明 |
| --- | --- |
| event | 事件名称（可选），客户端据此分派 |
| data | 数据载荷，支持多行合并 |
| id | 事件 ID（可选），用于断线重连 |
| retry | 重连等待毫秒数（可选） |

**关键规则**：一个事件可以有多行 `data:` 字段，客户端需要将它们用 `\n` 拼接；**空行**标志一个事件的结束边界。

**SSE vs WebSocket vs 长轮询**

| 特性 | SSE | WebSocket | 长轮询 |
| --- | --- | --- | --- |
| 通信方向 | 服务器 → 客户端 | 双向 | 客户端 → 服务器 |
| 协议 | HTTP | WS/WSS | HTTP |
| 自动重连 | 浏览器原生支持 | 需手动实现 | 不适用 |
| 实现复杂度 | 低 | 中 | 低 |
| 代理/防火墙 | 友好（标准 HTTP） | 可能被拦截 | 友好 |
| 适用场景 | 流式输出、通知推送 | 实时聊天、协同编辑 | 简单实时场景 |

本项目选择 SSE 的核心原因：**AI Agent 的响应本质上是"请求 → 流式回复"的单向推送模型**，SSE 在 HTTP 层面即可实现，无需引入额外的协议升级和连接管理复杂度。

后端实现详解

SSE 端点层 — ChatController

`ChatController` 是一个**瘦 Controller**，仅负责 HTTP 协议解析和参数校验，Agent 执行编排完全委托给 `ChatAgentExecutor`。

```java

// ChatController.java
@PostMapping("/{sessionId}")
@SaCheckLogin
public SseEmitter chat(@PathVariable String sessionId, @RequestBody ChatRequest request) {
    String userId = StpUtil.getLoginIdAsString();
    AgentSessionContext sessionCtx = new AgentSessionContext(userId, sessionId);
    
    // 1. 持久化用户消息
    chatHistoryService.saveUserMessage(sessionId, userId, message);
    
    // 2. 优雅中断残留的同一 session 执行流（本地 + 集群广播）
    agentExecutor.interruptPrevious(sessionId);
    
    // 3. 创建 SseEmitter（30 分钟超时）
    SseEmitter emitter = agentExecutor.createEmitter();
    
    // 4. 判断 continuation 信号：复用上一轮 Agent 或走 MasterAgent 全新协调
    String activeAgent = activeAgentSessionStore.getActiveAgent(sessionId);
    if (activeAgent != null && isContinuation(message)) {
        Agent targetAgent = agentRegistry.getAgent(activeAgent);
        agentExecutor.executeAgent(targetAgent, inputMessages, message, emitter, sessionCtx);
    } else {
        agentExecutor.executeAgent(null, inputMessages, message, emitter, sessionCtx);
    }
    
    return emitter;
}
```

这里面会创建一个SseEmitter。

SseEmitter创建

```text
/**
 * 创建新的 SseEmitter 实例（统一超时配置）。
 */
public SseEmitter createEmitter() {
    return new SseEmitter(SSE_EMITTER_TIMEOUT_MILLIS);
}
```

`SseEmitterRegistry` 维护 `sessionId → SseEmitter` 的映射关系，供 `ProgressNotifierHook` 在 Agent 执行过程中实时获取 emitter 推送进度。

```java

// SseEmitterRegistry.java
@Component
public class SseEmitterRegistry {
    private final Map<String, SseEmitter> emitters = new ConcurrentHashMap<>();

    public void register(String sessionId, SseEmitter emitter) {
        emitters.put(sessionId, emitter);
        // 绑定三个回调，确保 emitter 生命周期结束时自动清理
        emitter.onCompletion(() -> emitters.remove(sessionId, emitter));
        emitter.onTimeout(() -> emitters.remove(sessionId, emitter));
        emitter.onError(e -> emitters.remove(sessionId, emitter));
    }
}
```
