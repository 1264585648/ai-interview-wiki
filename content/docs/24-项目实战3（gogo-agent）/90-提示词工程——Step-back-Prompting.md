# ✅提示词工程——Step-back Prompting

这个主要是用在我们的问题改写中，之前know-engine那个项目也用了类似的方式。他主要解决的问题就是**用户问得太具体/太模糊，具体到隐藏了他真正想要的答案**。

以 西湖附近那个全季怎么样 为例，用户表面上问"全季酒店"，但他真实的诉求可能是：

- 这家酒店价格多少？符合差旅住宿标准吗？
- 位置好不好？离阿里巴巴远不远？
- 有没有更好的替代？

如果下游 Agent 只看到"那个全季怎么样"，它会去查 全季酒店 的信息，答案很片面；下游要么回答"全季是一家经济型酒店品牌"（正确废话），要么回答"评分 4.2"（信息孤岛）。**问题被问得越具体，答案越容易片面**。

Step-back Prompting 就是为了这一场景而生：让 LLM 在正式回答前，**先退一步把问题抽象化/富化**，再回到具体细节。这样下游拿到的是一个"扁平的、显式化的意图"，而不是一个"缩过水的表述"。

前面讲RAG的时候提到过这个：

打开 query-rewriting-agent-system.md，你会在"改写规则"里发现第 4 条：

```text
### 4. Step-back 改写

- 当用户问题过于具体、模糊或带有强烈假设时，先退一步，生成一个更通用、更基础的问题版本，帮助理解真实意图。
- 例如：
  - 用户：`西湖附近那个全季怎么样？`
  - Step-back：`用户想了解杭州西湖附近全季酒店的相关信息（价格、位置、评价、是否符合差旅政策）。`
- Step-back 改写后的问题用于辅助理解，最终 `rewritten_question` 仍应保留具体细节。
```

这里有三点特别值得学：

1. **触发条件明确写死在规则里**：不是让 LLM 自由判断"要不要 step-back"，而是三种情形——过于具体、模糊、带强烈假设——命中任一即触发。
2. **step-back 只做辅助推理，不替代原始问题**：最终交给下游的 rewritten_question 依然是具体版本，step-back 版本只作为 LLM 内部的"参考视角"。这一点非常关键，下面会展开。
3. **step-back 是"意图还原"，不是"泛化到无用"**：西湖附近那个全季 被展开成 杭州西湖附近全季酒店的价格、位置、评价、是否符合差旅政策，抽象层级刚好——够宽到覆盖用户潜在需求，够窄到还能查到答案。
