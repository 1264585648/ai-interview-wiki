# ✅差旅政策工具定义及开发

差旅政策不是一份静态文档，而是**"用户职级 × 目的城市等级"**两个维度共同决定的一张查找表：

- 同一个人去北京 vs 去昆明，酒店上限不一样。
- 同一个城市，P6 vs P8 的舱位/上限也完全不同。

所以 Agent 不能只靠 RAG "语义近似"就回答"我去 X 城市的住宿标准是多少"——**必须走一个能拿到用户身份、能查数据库的确定性工具**，这就是 PolicyTools 存在的理由。

后面要讲的那个InfoAgent，其实做了政策查询的"双通道"（[77-✅差旅政策的双通道支持.md](77-✅差旅政策的双通道支持.md) ）：通道 1（RAG）：处理"差旅制度对超标是怎么规定的？"这类**语义/规则性**问题，召回内容是参考。通道 2（Tool）：处理"我去上海的住宿标准？""我这单超标吗？"这类**精确/可校验**问题。**（本文主要讲这个）**

为什么需要这个工具

先把"如果没有 PolicyTools 会怎样"想清楚，价值就自然浮现。

**方案 A：全都塞进 system prompt**——把 12 条政策规则、几十个城市列表全部拼进提示词。缺点很直接：token 恒定膨胀；换职级/加城市要改代码；LLM 还有可能算错"P7 去昆明属于哪一档"。

**方案 B：全部走 RAG**——把政策文档灌进向量库让模型语义检索。缺点是 RAG 精度不足以给出"具体数字"，且**用户身份（"我"是谁、职级几档）无法向量化**，模型很容易把别人的政策当成"你的"标准回复出去，合规风险高。

**方案 C（当前实现）：定义一对确定性工具，把"查询 + 校验"下沉到业务代码里**——

- 用户身份从 AgentSessionContext（框架注入，不进对话上下文）取；
- 城市等级、职级映射走配置和数据库；
- LLM 只负责"识别这是政策类问题 → 决定调 query 还是 check → 组织自然语言输出"。

这样得到的三个直接好处：

1. **数据永远最新**：DB 改一条规则立即生效，不用改代码/重训。
2. **对模型透明**：LLM 看到的接口只有 city 和 order_summary，不用管"用户是谁"，减少幻觉。
3. **合规可审计**：所有政策计算发生在 Java 侧，日志里能追到 userId + city + tier + policy，出问题能复盘。

工具类定义：PolicyTools

![](assets/9be5da0a2617.png)

```text
@Component
public class PolicyTools {

    private static final Logger logger = LoggerFactory.getLogger(PolicyTools.class);

    @Autowired
    private TravelPolicyService travelPolicyService;   // 政策计算引擎

    @Tool(name = "query_travel_policy",
            description = "查询指定用户和目的城市的差旅政策标准（餐标、酒店标准、交通补贴等）")
    public String queryTravelPolicy(
            AgentSessionContext sessionCtx,              // ← 框架注入的隐式参数，无 @ToolParam
            @ToolParam(name = "city", description = "目的城市") String city) {

        // 1) 优先命中会话内缓存：同一次对话里反复问"我去 X 的标准"直接返回，避免重复查库
        String travelPolicy = sessionCtx.getTravelPolicy(city);
        if (travelPolicy != null) {
            logger.info("[TOOL][query_travel_policy] hit cache, city={}", city);
            return travelPolicy;
        } else {
            logger.info("[TOOL][query_travel_policy] miss cache");
            String userId = sessionCtx.getUserId();
            logger.info("[TOOL][query_travel_policy] userId={}, city={}", userId, city);
            // 2) 未命中缓存 → 走 service 完整链路（职级 + 城市等级 + DB 规则）
            TravelPolicy policy = travelPolicyService.getPolicy(userId, city);
            // 3) 统一序列化成 JSON 返回给 LLM——工具返回值必须是可读文本
            String result = JSON.toJSONString(policy);
            logger.info("[TOOL][query_travel_policy] result={}", result);
            // 4) 回填缓存
            sessionCtx.setTravelPolicy(city, result);
            return result;
        }
    }

    @Tool(name = "check_travel_policy",
            description = "校验行程或订单是否符合差旅政策，返回合规结果和超标说明")
    public String checkTravelPolicy(
            AgentSessionContext sessionCtx,
            @ToolParam(name = "city", description = "目的城市") String city,
            @ToolParam(name = "order_summary",
                    description = "订单摘要JSON，例如 {\"type\":\"HOTEL\",\"amount\":450}") String orderSummary) {

        String userId = sessionCtx.getUserId();
        logger.info("[TOOL][check_travel_policy] userId={}, city={}, orderSummary={}",
                userId, city, orderSummary);
        // 注意：这里没有走缓存 —— 见 2.2 末尾的说明
        TravelPolicy policy = travelPolicyService.getPolicy(userId, city);
        PolicyCheckResult result = travelPolicyService.checkCompliance(orderSummary, policy);
        String json = JSON.toJSONString(result);
        logger.info("[TOOL][check_travel_policy] done");
        return json;
    }
}
```

用户ID参数注入

TravelPolicyService

工具本身只是薄壳，真正干活的是 service。

```text
@Service
public class TravelPolicyService {

    @Autowired private UserProfileRepository userProfileRepository;         // 查用户职级
    @Autowired private TravelPolicyProperties travelPolicyProperties;       // 读 city-tier.yml
    @Autowired private TravelPolicyRuleRepository travelPolicyRuleRepository;  // 查政策规则表

    public TravelPolicy getPolicy(String userId, String destinationCity) {
        String level    = resolveUserLevel(userId);           // ① 拿职级
        String cityTier = resolveCityTier(destinationCity);   // ② 拿城市等级
        return buildPolicy(level, cityTier);                  // ③ 查规则表拼装
    }

    // ① 用户职级：不存在/未配置就直接抛，绝不给默认值——避免"P0 走 P8 政策"这种静默事故
    private String resolveUserLevel(String userId) {
        if (userId == null || userId.isBlank()) {
            throw new IllegalArgumentException("user_id 不能为空");
        }
        UserProfile profile = userProfileRepository.findByUserId(userId)
                .orElseThrow(() -> new IllegalArgumentException(
                        "用户档案不存在，无法获取差旅政策：userId=" + userId));
        String level = profile.getLevel();
        if (level == null || level.isBlank()) {
            throw new IllegalStateException(
                    "用户未配置职级，无法获取差旅政策：userId=" + userId);
        }
        return level;
    }

    // ② 城市等级：从 city-tier.yml 读取，未列出的城市默认"其他"
    private String resolveCityTier(String destinationCity) {
        if (destinationCity == null || destinationCity.isBlank()) return "其他";
        String city = destinationCity.trim();
        if (travelPolicyProperties.getTier1Cities().contains(city))    return "一线";
        if (travelPolicyProperties.getNewTier1Cities().contains(city)) return "新一线";
        if (travelPolicyProperties.getTier2Cities().contains(city))    return "二线";
        return "其他";
    }

    // ③ 组装政策：这里有个隐蔽的收敛动作——DB 规则表只区分 3 档（一线/新一线/其他），
    //   所以本地识别到的"二线"会在这里被折叠成"其他"
    private TravelPolicy buildPolicy(String level, String cityTier) {
        int levelNum = parseLevelNum(level);
        String policyTier = ("一线".equals(cityTier) || "新一线".equals(cityTier))
                ? cityTier : "其他";

        TravelPolicyRule rule = travelPolicyRuleRepository
                .findByLevelAndCityTier(levelNum, policyTier)
                .orElseThrow(() -> new IllegalStateException(
                        String.format("未找到匹配的差旅政策规则：level=%s(num=%d), cityTier=%s",
                                level, levelNum, policyTier)));

        // 从 DB 实体拷贝到对外 DTO；不直接返回 TravelPolicyRule 是为了解耦持久化字段
        TravelPolicy policy = new TravelPolicy();
        policy.setUserLevel(level);
        policy.setCityTier(cityTier);   // 注意这里存的是识别到的原始 tier（可能是"二线"）
        policy.setFlightClass(rule.getFlightClass());
        policy.setTrainSeatClass(rule.getTrainSeatClass());
        policy.setHotelLimit(rule.getHotelLimit());
        policy.setHotelStarLimit(rule.getHotelStarLimit());
        policy.setDailyMealLimit(rule.getDailyMealLimit());
        policy.setDailyTransportLimit(rule.getDailyTransportLimit());
        policy.setApprovalThreshold(rule.getApprovalThreshold());
        policy.setAdvanceBookingDays(rule.getAdvanceBookingDays());
        return policy;
    }

    private static int parseLevelNum(String level) {
        String digits = level.replaceAll("[^0-9]", "");   // "P7" → "7"
        if (digits.isEmpty()) {
            throw new IllegalArgumentException("职级格式无效，无法解析数字：" + level);
        }
        return Integer.parseInt(digits);
    }

    // 合规校验：按订单 type 分派 —— 目前 3 种业务
    public PolicyCheckResult checkCompliance(String orderSummaryJson, TravelPolicy policy) {
        PolicyCheckResult result = PolicyCheckResult.compliant();
        JSONObject order = JSON.parseObject(orderSummaryJson);
        if (order == null) return result;

        String type = order.getString("type");
        double amount = order.getDoubleValue("amount");

        if ("FLIGHT".equalsIgnoreCase(type)) {
            String flightClass = order.getString("flightClass");
            // 用 contains 是刻意的：DB 里 P7 存的是 "经济舱/商务舱"，可以匹配两种
            if (flightClass != null && !policy.getFlightClass().contains(flightClass)) {
                result.setCompliant(false);
                result.getViolations().add("机票舱位超出政策标准：允许 " + policy.getFlightClass());
            }
        } else if ("HOTEL".equalsIgnoreCase(type)) {
            if (amount > policy.getHotelLimit()) {
                result.setCompliant(false);
                result.getViolations().add("酒店金额超出政策上限：" + policy.getHotelLimit());
                result.getSuggestions().add("建议选择 " + policy.getHotelLimit() + " 元以下酒店");
            }
        } else if ("TRAIN".equalsIgnoreCase(type)) {
            String seatClass = order.getString("seatClass");
            if (seatClass != null && !seatClass.equalsIgnoreCase(policy.getTrainSeatClass())) {
                result.setCompliant(false);
                result.getViolations().add("火车座位超出政策标准：允许 " + policy.getTrainSeatClass());
            }
        }
        return result;
    }
}
```

有个小坑：**YAML key 必须是 ASCII**，中文城市名只能放到 List 的值里，不能作为 key。Spring 松散绑定对中文 key 的兼容不完全。

**政策规则表** — src/main/resources/db/schema.sql（节选）：

```text
CREATE TABLE IF NOT EXISTS `travel_policy_rule` (
    `id`                    BIGINT      NOT NULL AUTO_INCREMENT,
    `level_min`             INT         NOT NULL COMMENT '职级区间下限（数字）',
    `level_max`             INT         NOT NULL COMMENT '职级区间上限（99表示无上限）',
    `city_tier`             VARCHAR(16) NOT NULL COMMENT '城市等级：一线/新一线/其他',
    `flight_class`          VARCHAR(32) DEFAULT NULL,
    `train_seat_class`      VARCHAR(16) DEFAULT NULL,
    `hotel_limit`           DOUBLE      NOT NULL DEFAULT 0,
    `hotel_star_limit`      INT         NOT NULL DEFAULT 4,
    `daily_meal_limit`      DOUBLE      NOT NULL DEFAULT 0,
    `daily_transport_limit` DOUBLE      NOT NULL DEFAULT 0,
    `approval_threshold`    DOUBLE      NOT NULL DEFAULT 0,
    `advance_booking_days`  INT         NOT NULL DEFAULT 3,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_level_city` (`level_min`, `level_max`, `city_tier`)
) ENGINE = InnoDB;
```

Mapper / Repository 是最薄的一层：

```text
// TravelPolicyRuleMapper.java
@Mapper
public interface TravelPolicyRuleMapper extends BaseMapper<TravelPolicyRule> {
    @Select("SELECT * FROM travel_policy_rule "
          + "WHERE level_min <= #{levelNum} AND level_max >= #{levelNum} "
          + "  AND city_tier = #{cityTier} "
          + "LIMIT 1")
    TravelPolicyRule findByLevelAndTier(@Param("levelNum") int levelNum,
                                        @Param("cityTier") String cityTier);
}

// TravelPolicyRuleRepositoryImpl.java
@Repository
public class TravelPolicyRuleRepositoryImpl implements TravelPolicyRuleRepository {
    @Autowired private TravelPolicyRuleMapper travelPolicyRuleMapper;
    @Override
    public Optional<TravelPolicyRule> findByLevelAndCityTier(int levelNum, String cityTier) {
        return Optional.ofNullable(
                travelPolicyRuleMapper.findByLevelAndTier(levelNum, cityTier));
    }
}
```

之所以要 Repository 接口而不是 service 直接调 Mapper，是为了让 service 的单测能用假实现替换（后面"扩展"小节会用到）。
