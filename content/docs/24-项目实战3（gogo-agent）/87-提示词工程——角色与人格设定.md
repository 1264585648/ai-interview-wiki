# ✅提示词工程——角色与人格设定

在 gogo-agent 项目中，一共有 **11 个 system prompt** 文件，对应 11 个不同职责的智能体。每个 prompt 的第一行几乎都是"你是XXX"或"你负责XXX"——这不是随手一写的开头，而是整个提示词工程的**锚点**。

角色设定的本质是：**通过语言约束 LLM 的行为空间，让它从"无所不能的通用助手"变成"专注解决特定问题的专家"**。角色越清晰，LLM 的输出越可控、越专业、越不容易跑偏。

![](assets/4582df9c08a4.png)

翻遍 gogo-agent 的所有 prompt，会发现一个稳定的四层结构：

第一层：身份定义（我是谁） ↓ 第二层：职责边界（我做什么、不做什么） ↓ 第三层：行为约束（我怎么做、按什么规则做） ↓ 第四层：输出风格（我用什么语气、什么格式说话）

以 InfoAgent 为例，可以看到这四层的完整体现：

```text
# 角色与核心定位                                          ← 第一层：身份

你是 GoGo 智能差旅系统的**信息查询助手（InfoAgent）**，
专门负责回答用户关于目的地旅游景点、签证入境政策、
差旅政策标准以及通用公共信息（天气、交通等）方面的查询。

你的核心职责是：                                          ← 第二层：职责
1. **精准查询**：根据用户问题选择合适的工具获取信息。
2. **整合回答**：将工具返回的原始数据整理成自然语言。
3. **补充建议**：给出相关的差旅建议或注意事项。

# 禁止行为                                                ← 第二层：边界
- 不得修改、提交、取消任何差旅单/审批。
- 不得代替用户做决策（例如"我帮你订酒店"）。
- 不要反问用户获取不必须的信息。

## 政策查询双通道说明                                     ← 第三层：行为
差旅政策类查询**必须**根据场景选择正确的通道...

# 回答风格                                                ← 第四层：风格
- 使用中文回答，语气专业、简洁、友好。
- 对查询结果进行结构化呈现（如分点、加粗关键信息）。
```

这四层不是可有可无的模块，而是一个**递进依赖**：没有身份定义，职责无从谈起；没有职责边界，行为规则无处应用；没有行为约束，输出风格也就没有基础。
