# ✅市面上可用的旅行相关skill/mcp工具对比

在我们的项目中，我们需要查询酒店、机票、火车票，并且还需要做预订、取消等等，这些我们没办法自己做，需要依赖第三方能力。

在以前，我们只能调第三方接口，但是ai时代，我们可以通过第三方的skill或者mcp来实现，我找遍了市面上的所有旅行服务商提供了可被 AI Agent 调用的 MCP 接口或 Skill 工具。它们的能力差异很大——有的只能搜索，有的支持全链路预订；有的绑定 C 端账号，有的完全 API 化。本文从**功能覆盖、调用限额、账号体系、预订能力**四个维度做横向对比，帮助开发者根据自己的场景选择合适的工具组合。

各平台详细分析

途牛（Tuniu）

**接入方式**：MCP 协议 / CLI 工具（tuniu-cli）

**官方文档**：[https://open.tuniu.com/mcp/docs/apidoc/mcp/hotelMCP.html](https://open.tuniu.com/mcp/docs/apidoc/mcp/hotelMCP.html)

**功能覆盖**：

| 品类 | 搜索 | 查询 | 预订 | 取消 |
| --- | --- | --- | --- | --- |
| 酒店 | ✅ | ✅ | ✅ | ❌ |
| 机票 | ✅ | ✅ | ✅ | ✅ |
| 火车票 | ✅ | ✅ | ✅ | ✅ |

**调用限额**：5 次/分钟，50 次/天

**账号体系**：开放平台账号与途牛 C 端会员通过手机号绑定。通过 MCP 接口发起的访问统一记录为该会员的访问行为，用于会员下单、权益归属与用量统计。

**优势**：品类覆盖全（机票+酒店+火车票三合一），预订链路完整。

**劣势**：限额极低（5次/分钟），酒店不支持取消，C 端账号绑定意味着多用户场景需要每人一个途牛账号。——但是这个限额我实际测试的时候并没有触发过。

航班管家（Flight Manager / 133.cn）

**接入方式**：MCP 协议 / Skill（flight-manager、huoli-car-ai）

**官方文档**：

- API Key 获取：<br>[mcpApiKey · h5.133.cn](https://h5.133.cn/webapp/pages/mcpApiKey?zhuti=HBGJ&uid=H5GNoxOAM9AizyUeYkP-IIso)
- 机票+酒店 Skill：<br>[https://skillhub.cn/skills/flight-manager-hotelai](https://skillhub.cn/skills/flight-manager-hotelai)
- 专车 Skill：<br>[https://skillhub.cn/skills/huoli-car-ai](https://skillhub.cn/skills/huoli-car-ai)

**功能覆盖**：

| 品类 | 搜索 | 查询 | 预订 | 取消 | 其他 |
| --- | --- | --- | --- | --- | --- |
| 机票 | ✅ | ✅ | ✅ | ✅ | 退改签、发票 |
| 酒店 | ✅ | ✅ | ✅ | ✅ | 查询订单 |
| 专车接送 | ✅ | ✅ | ✅ | ✅ | — |

**调用限额**：50 次/分钟，500 次/天

**账号体系**：独立 API Key，按用户管理。

**优势**：限额最高（500次/天，是途牛的 10 倍），功能最完整（含退改签、发票、专车），唯一支持用车服务的平台。

**劣势**：不支持火车票，品类少于途牛和携程。预订之后的订单，在自己的账号上看不到？？？

飞猪（Fliggy / FlyAI）

**接入方式**：MCP 协议 / CLI 工具

**官方文档**：flyai.open.fliggy.com

**功能覆盖**：

| 品类 | 搜索 | 查询 | 预订 | 取消 |
| --- | --- | --- | --- | --- |
| 酒店 | ✅ | ✅ | ❌ | ❌ |
| 机票 | ✅ | ✅ | ❌ | ❌ |
| 火车票 | ✅ | ✅ | ❌ | ❌ |

**调用限额**：100 次/天（初始赠送 5000 次）

**账号体系**：飞猪开放平台账号。

**优势**：初始额度慷慨（5000 次），搜索覆盖全（机票+酒店+火车票），背靠阿里生态数据丰富。

**劣势**：**只能搜索和查询，完全不支持预订**。适合做候选搜索和比价，无法完成交易闭环。

Rolling-Go（RGH）

**接入方式**：CLI 工具（rgh）

官方地址：[https://rollinggo.store/solutions/skills/rollinggo-searchhotel](https://rollinggo.store/solutions/skills/rollinggo-searchhotel)

**功能覆盖**：

| 品类 | 搜索 | 查询 | 预订 | 支付 |
| --- | --- | --- | --- | --- |
| 酒店 | ✅ | ✅ | ✅ | ✅ |

**调用限额**：未公开明确限制。

**账号体系**：使用用户自己的账号预订，可查询到订单列表，支持直接支付。

**优势**：预订后可以在系统内完成付款，不需要跳转外部页面。订单与用户个人账号绑定，可查询历史订单。

**劣势**：只有酒店品类，无机票、火车票、用车服务。

携程问道（Wendao）

**接入方式**：Skill

**官方文档**：[https://skillhub.cn/skills/wendao-skill](https://skillhub.cn/skills/wendao-skill)

**功能覆盖**：

| 品类 | 搜索 | 查询 | 预订 | 取消 |
| --- | --- | --- | --- | --- |
| 酒店 | ✅ | ✅ | ⚠️ | ❌ |
| 机票 | ✅ | ❌ | ❌ | ❌ |
| 火车票 | ✅ | ❌ | ❌ | ❌ |

**调用限额**：未公开限制。

**账号体系**：携程账号。

**重要限制**：问道服务目前只能帮用户完成到"下单页"这一步，**无法在后端直接代付/代提交订单**（涉及身份证、支付、发票抬头等实名信息）。酒店"预订"实际上是生成下单链接，需要用户手动完成最后一步。

**优势**：携程作为国内最大 OTA，搜索数据覆盖最全、价格最有竞争力。

**劣势**：无法完成交易闭环，本质上是"搜索+引导下单"，不是真正的 API 预订。

打车类服务

| 平台 | 功能 | 限制 |
| --- | --- | --- |
| 腾讯出行 | 即时打车 | 不支持预约 |
| 高德打车 | 打车 | 需唤起高德 APP，无纯 API 能力 |
| 滴滴 | 即时打车 | 不支持预约 |
| **航班管家专车** | **预订、查询、取消** | **唯一支持全流程的用车服务** |

目前打车领域，只有航班管家的专车接送服务（huoli-car-ai）提供了完整的 MCP/Skill 接口，支持预约、查询和取消。其他平台要么不支持预约，要么需要唤起原生 APP。
