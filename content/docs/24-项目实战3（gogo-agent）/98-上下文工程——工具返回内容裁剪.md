# ✅上下文工程——工具返回内容裁剪

gogo-agent 的行程规划 Agent 单次规划可能调用十几次工具（查审批单、查偏好、查政策、搜机票、搜酒店、搜火车、打分、调 plan_itinerary、送审、修复……），如果每次工具结果都原文存入 memory，十几轮下来 token 轻松突破 128K 窗口的 75%——触发框架的自动压缩，而框架压缩需要额外调用一次 LLM，既增加延迟又增加成本。

所以 gogo-agent 的设计理念是：**尽量在工具结果进入 memory 之前就把它裁瘦——能在编码时只返回决策所需的最小集就不返回全量，能在 PostActing Hook 里去掉冗余字段就不让它进 memory，能在 PreReasoning 时折叠已过时的技能正文就不让它占用 LLM 输入**。三道防线层层递进，让框架的自动压缩（六级策略）尽可能晚触发、少触发。

在我们的行程规划的智能体中，我们会调用tuniu cli做酒店、机票、火车票的查询，这个cli会返回很多内容，内容特别的大，而里面有一些重复信息，还有一些我们不需要的信息，这些信息我们其实都不太需要的。那么就可以针对工具的返回内容做裁剪和压缩。

CliResultCompressHook监听 PostActingEvent——即工具执行完毕后、结果消息写入 Agent memory 之前。它对工具返回的 JSON 文本做四步优化：

**第一步**：识别 execute_shell_command 的包装格式。tuniu CLI 通过 shell 执行，结果被框架包装为 &lt;returncode&gt;0&lt;/returncode&gt;&lt;stdout&gt;JSON&lt;/stdout&gt;&lt;stderr&gt;&lt;/stderr&gt;，Hook 只抽取 &lt;stdout&gt; 内的 JSON 做优化，前后包装原样保留：

```text
private String optimizeText(String text) {
    int open = text.indexOf(STDOUT_OPEN);
    int close = text.lastIndexOf(STDOUT_CLOSE);
    if (open >= 0 && close > open) {
        int jsonStart = open + STDOUT_OPEN.length();
        String inner = text.substring(jsonStart, close);
        String optimizedInner = optimizeJson(inner);
        return text.substring(0, jsonStart) + optimizedInner + text.substring(close);
    }
    return optimizeJson(text);
}
```

**第二步**：structuredContent 去重。MCP 协议返回的 JSON 里同一份数据在 content[0].text 和 structuredContent 各存一份。Hook 发现两者共存时直接删除 structuredContent：

```text
private void cleanObject(JSONObject obj) {
    if (obj.containsKey(STRUCTURED_CONTENT_KEY) && isNonEmptyContentArray(obj.get(CONTENT_KEY))) {
        obj.remove(STRUCTURED_CONTENT_KEY);
    }
    ...
}
```

**第三步**：黑名单字段移除 + 递归去空。对 LLM 决策无用的字段（如航司 logo 图片 URL、内部 queryId、机型代码）无条件剔除；null/空字符串/空数组/空对象递归清理：

```text
private static final Set<String> DROP_KEYS = Set.of(
        "airComImageUrl", "queryId", "craftType", "planModel");

obj.keySet().removeAll(DROP_KEYS);
// ... 递归去空
```

**第四步**：紧凑序列化。去掉格式化的缩进/换行，用 fastjson2 默认的紧凑输出：

```text
String compact = JSON.toJSONString(cleaned);
if (compact.length() >= trimmed.length()) {
    return null;  // 无体积收益则跳过
}
```

还有一个容易忽略的细节——optimizeEmbeddedJson会递归处理"JSON 字符串里内嵌的 JSON 字符串"（MCP content[0].text 本身就是一个 JSON 字符串，里面的值又可能是 JSON），确保多层嵌套的冗余也被清理。

最后写回的关键——**必须同时重建 ****ToolResultBlock**** 和 ****ToolResultMsg**，因为框架写入 memory 的是后者：

```text
ToolResultBlock newResult = new ToolResultBlock(
        toolResult.getId(), toolResult.getName(), newOutput, toolResult.getMetadata());
event.setToolResult(newResult);

Msg newMsg = ToolResultMessageBuilder.buildToolResultMsg(newResult, toolUse, agentName);
event.setToolResultMsg(newMsg);
```

这个 Hook 挂载在 ItineraryPlanAgent、BookingAgent、InfoAgent 上（都是会调用 tuniu CLI 的 Agent），**MasterAgent 未挂载**（它不调外部 CLI）。
