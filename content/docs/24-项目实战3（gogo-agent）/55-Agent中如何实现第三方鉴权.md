# ✅Agent中如何实现第三方鉴权？

在我们的项目中，需要调外部的接口来做业务操作，比如预定火车票、机票，这些都是需要用户做登录的。这样用户下单后就能在自己的账号中看到对应的订单。

我们用的第三方预定工具主要是tuniu cli、rolling-go-hotel，他们都是通过CLI来实现的。

什么是CLI

CLI（Command Line Interface，命令行界面）是一种通过键盘输入文本命令来与计算机交互的方式。

Agent 调用工具的本质，其实就是执行命令。CLI 工具天然就是 Agent 可以调用的函数——给定名称和参数，返回结果。

相比于让 Agent 去模拟人类操作图形界面（比如用视觉识别去找按钮、点菜单），CLI 跳过了视觉识别的步骤，直接通过标准化命令与软件交互。这不仅速度极快，而且准确率极高。

在 Agent 系统中，Token 消耗和稳定性是核心考量。

GUI 操作需要模型不断推理“下一步点哪里”，极其消耗 Token。而 CLI 是确定性的代码，同样的输入永远返回同样的结果，执行过程几乎零 Token 消耗。

现代 CLI 工具通常输出结构化的 JSON 数据，Agent 可以直接解析，不需要像处理网页文本那样去“猜”意思，大幅降低了幻觉风险。

CLI 鉴权与 Web 鉴权的区别

Web 鉴权依赖浏览器，流程通常是“点击登录 → 跳转授权页 → 授权后重定向回原网站 → 换取并存储 Token”。而 CLI 运行在纯文本的终端环境，无法渲染网页，通常也没有内置的 HTTP 服务器来接收授权后的回调重定向。

Web 应用可以将 Token 存储在浏览器的 Cookie 或 localStorage 中。CLI 进程结束后内存会清空，因此必须将获取到的 Token 持久化到本地文件系统中。

CLI怎么做鉴权

CLI一般有3种常见的鉴权模式。它们的核心都是获取并存储一个**Token**（或 API Key），而不是用户的密码，以确保更高的安全性。

**Token 直接配置**

用户手动获取 Token，然后通过环境变量或配置文件的方式提供给 CLI 工具。

- **优点**：实现成本为零，无需在 CLI 中编写复杂的鉴权逻辑。
- **缺点**：用户需要自行寻找生成 Token 的位置、复制粘贴并管理其生命周期，对新手不友好。还有就是可能存在一些泄露的风险。

**OAuth Device Flow**

用户在终端看到一个验证码，然后在浏览器中打开指定网址并输入该验证码完成授权。CLI 工具在后台轮询等待授权结果。

- **优点**：用户体验好，只需在浏览器点击授权即可，无需手动复制 Token。安全性高，CLI 进程接触不到用户密码。
- **缺点**：需要在 OAuth 平台注册应用，并实现轮询、超时和错误处理等逻辑。

**OAuth PKCE + 本地回调**

CLI 工具在本地启动一个临时 HTTP 服务器（如 `http://localhost:9999/callback`），引导用户在浏览器完成授权，授权后浏览器重定向到该本地地址，CLI 接收授权码并换取 Token。

- **优点**：全自动，用户只需在浏览器点击授权，比 Device Flow 少一步输入验证码的操作。
- **缺点**：需要在本地启动 HTTP 服务器，可能被防火墙拦截或遇到端口占用问题。

在我们的项目中，主要涉及到了第一种和第三种这两种方案。
