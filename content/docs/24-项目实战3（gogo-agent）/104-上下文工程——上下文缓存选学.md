# ✅上下文工程——上下文缓存（选学）

关于利用百炼的隐式缓存的方案前面讲过了，这里讲另外一种——显示缓存

隐式缓存是服务端自动的，但框架可以显式给某些消息打「cache_control」标记，提示服务端「这几段值得缓存、按缓存规则处理」。在 AgentScope 里就是 GenerateOptions.cacheControl(true)——开启后框架会自动在每次请求时给**系统消息**和**最后一条消息**加上 cache_control 标记。可以把它理解为「主动告诉服务端：请对我的固定前缀和最新增量做缓存优化」。

![](assets/92930723f1f4.png)

（需要注意的是，显示缓存和隐式缓存不会同时生效，如果开了显示缓存了之后，隐式缓存就没必要了，但是这两个方案我们都给大家讲一下。正常情况下建议直接用隐式缓存就够了）

项目中，所有 Agent 构建 GenerateOptions 时都开了缓存。

```text
// BaseSubAgent.java:174-188
public GenerateOptions getEnableThinkingGenerateOptions(Integer thinkingBudget) {
    return GenerateOptions.builder()
            // 开启缓存，框架会自动在每次请求时对 system messages 和 最后一条消息 加上 cache_control（…bailian…）
            .cacheControl(true)
            // 深度思考模型有时会生成冗长的推理过程…通过 thinking_budget 可设推理过程的最大 Token 数
            .thinkingBudget(thinkingBudget)
            .build();
}

public GenerateOptions getGenerateOptions() {
    return GenerateOptions.builder()
            // 开启缓存，框架会自动在每次请求时对 system messages 和 最后一条消息 加上 cache_control（…bailian…）
            .cacheControl(true)
            .build();
}
```

`cacheControl(true)`  的语义：框架自动给系统消息和最后一条消息打缓存标记。

在做这个方案的时候，我踩过一个很隐蔽的坑：行程规划 Agent 会在「规划阶段（开思考）」和「执行阶段（关思考）」之间切换，切换靠**重建 ****GenerateOptions**。而一旦重建，如果新的 options 忘了带 cacheControl(true)，缓存标记就丢了、前面的稳前缀白稳了。后来在PlanAwareThinkingHook.java 在两处重建里都显式重申：

```text
// PlanAwareThinkingHook.java:59-75
private void enableThinking(PreSummaryEvent event) {          // 最终总结阶段：开思考
    event.setGenerateOptions(GenerateOptions.builder()
            .cacheControl(true)
            .thinkingBudget(thinkingBudget)
            .build());
}

private void disableThinking(PreReasoningEvent event) {        // 执行阶段：关思考，快速跑
    event.setGenerateOptions(GenerateOptions.builder()
            // 保住隐式缓存
            .cacheControl(true)
            // 关闭思考
            .additionalBodyParam("enable_thinking", false)
            .build());
}
```
