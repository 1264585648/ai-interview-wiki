# ✅预订管理工具定义及开发

在行程管理这个Agent中，会涉及到预定相关的查询和操作（只有取消涉及，创建在BookingAgent中会调用）

和行程管理工具一样，我们提供了读和写两套工具。

- BookingReadTools：一个 @Tool — query_booking_record（按 booking_id / travel_order_id / biz_type / status 查询）。
- BookingWriteTools：一个 @Tool — cancel_booking（取消预订：机票/火车票走 CLI，酒店只标记内部状态）。

BookingReadTools

```text
@Component
public class BookingReadTools {

    @Autowired
    private BookingRecordRepository bookingRecordRepository;

    @Tool(name = "query_booking_record",
            description = "查询用户的外部预订记录（机票/酒店/火车票等）。可按内部预订单号 booking_id 精确查询详情，"
                          + "或按差旅单ID travel_order_id 查询该行程关联的所有预订，"
                          + "或按业务类型 biz_type、预订状态 status 过滤列表；均不传则返回该用户全部预订记录")
    public String queryBookingRecord(
            AgentSessionContext sessionCtx,
            @ToolParam(name = "booking_id",       required = false) String bookingId,
            @ToolParam(name = "travel_order_id",  required = false) String travelOrderId,
            @ToolParam(name = "biz_type",         required = false) String bizType,
            @ToolParam(name = "status",           required = false) String status) {

        String userId = sessionCtx.getUserId();

        // ① 精确查（按 booking_id）+ 租户校验：不属于当前用户直接过滤掉，避免越权
        if (bookingId != null && !bookingId.isBlank()) {
            BookingRecord record = bookingRecordRepository.findByBookingId(bookingId)
                    .filter(r -> userId != null && userId.equals(r.getUserId()))
                    .orElse(null);
            return JSON.toJSONString(record != null ? record
                    : Map.of("error", "booking not found"));
        }

        // ② 按差旅单查关联预订：内存二次过滤 bizType / status
        if (travelOrderId != null && !travelOrderId.isBlank()) {
            List<BookingRecord> records =
                    bookingRecordRepository.findByUserIdAndTravelOrderId(userId, travelOrderId);
            if (bizType != null && !bizType.isBlank()) {
                BookingType bt = BookingType.of(bizType);
                if (bt != null) records = records.stream()
                        .filter(r -> r.getBizType() == bt).collect(Collectors.toList());
            }
            if (status != null && !status.isBlank()) {
                BookingStatus bs = BookingStatus.of(status);
                if (bs != null) records = records.stream()
                        .filter(r -> r.getStatus() == bs).collect(Collectors.toList());
            }
            return JSON.toJSONString(records);
        }

        // ③ 校验 bizType / status（非法值给结构化错误）
        BookingType bizTypeEnum = null;
        if (bizType != null && !bizType.isBlank()) {
            bizTypeEnum = BookingType.of(bizType);
            if (bizTypeEnum == null) {
                return JSON.toJSONString(Map.of("error",
                        "无效的业务类型参数: " + bizType + "，可选值: FLIGHT/HOTEL/TRAIN"));
            }
        }
        // ④ 状态校验（略，与 ③ 同构）
        // ⑤ 按 bizType 或全量查询 + status 内存过滤
        List<BookingRecord> records = bizTypeEnum != null
                ? bookingRecordRepository.findByUserIdAndBizType(userId, bizTypeEnum)
                : bookingRecordRepository.findByUserId(userId);
        // ... status 过滤 + return
    }
}
```

1. **查询优先级 ****booking_id > travel_order_id > biz_type/status > 全部**：优先级写死在 if-return 的分支顺序里，避免"多个参数同时给会走什么分支"的歧义。这种"用代码结构表达优先级"比"用一个 queryMode 枚举参数"要清晰得多。
2. **userId**** 从 ****sessionCtx**** 而不是 ****@ToolParam**：前面讲过原因，同理。
3. **非法参数返回结构化错误**：&#123;"error": "无效的业务类型参数: XXX, 可选值: FLIGHT/HOTEL/TRAIN"&#125;——LLM 拿到后能直接翻译给用户。比抛 500 友好。

BookingWriteTools

看 cancel_booking 的主干（agent/tools/BookingWriteTools.java）：

```text
@Tool(name = "cancel_booking",
        description = "取消用户的一条外部预订记录。机票和火车票会同步调用平台取消接口；"
                      + "酒店目前无线上取消通道，仅标记内部状态为已取消并提示用户联系酒店。"
                      + "已取消的记录重复调用会直接返回成功（幂等）。")
public String cancelBooking(AgentSessionContext sessionCtx, String bookingId, String reason) {
    String userId = sessionCtx.getUserId();

    if (bookingId == null || bookingId.isBlank()) {
        return errorResponse("INVALID_PARAM", "booking_id 不能为空");
    }

    // 1. 查询并校验归属——取消是改存量记录，必须防越权
    BookingRecord record = bookingRecordRepository.findByBookingId(bookingId).orElse(null);
    if (record == null) {
        return errorResponse("BOOKING_NOT_FOUND", "预订记录不存在：" + bookingId);
    }
    if (!userId.equals(record.getUserId())) {
        return errorResponse("PERMISSION_DENIED", "无权操作该预订记录，归属用户不匹配。");
    }

    // 2. 幂等：已取消直接返回成功
    BookingType bizType = record.getBizType();
    if (record.getStatus() == BookingStatus.CANCELLED) {
        return successResult(bookingId, bizType, true, "该预订记录已处于取消状态，无需重复取消。");
    }

    // 3. 先调平台取消
    PlatformCancelOutcome outcome = cancelOnPlatform(bizType, record.getExternalOrderNo(), userId, bookingId);
    if (!outcome.proceed) {
        // ★事务一致性核心：平台失败 → 直接返回错误，内部状态一动不动
        return errorResponse("PLATFORM_CANCEL_FAILED", "外部平台取消失败，内部预订状态未变更。原因：" + outcome.message);
    }

    // 4. 只有平台取消成功，才翻转内部状态
    record.setStatus(BookingStatus.CANCELLED);
    if (reason != null && !reason.isBlank()) {
        record.setRemark(reason);
    }
    bookingRecordRepository.save(record);

    return successResult(bookingId, bizType, outcome.platformCancelled, "预订已取消。" + outcome.message);
}
```
