# ✅引入L1/L2之后意图识别不准确问题修复

有以下一个场景：

![](assets/97478c6ccc5d.png)

这个对话，被意图识别归为了"用户要求规划行程、做方案"。

原因是因为查询改写智能体，把我的两轮对话融合在一起时，改写成了"我本周五到周日，去三亚参加海天盛筵，请帮我安排出差行程。"

![](assets/e3636a32276e.png)

而这句话，本身是有歧义的，在我们的L1意图识别中，被划分到了行程规划的意图中。

针对这个问题，我们有很多优化手段，比如进一步调整L1的规则，增加约束或者反向排除之类的。但是既然问题是改写带来的，我们其实可以通过约束改写来解决，于是我们在问题改写的系统提示词中增加以下内容：

```text
### 6. 动作词保真原则（下游意图识别强依赖）

`rewritten_question` 会直接作为意图识别的输入，而意图识别对**动作动词**高度敏感（同一件事说成“申请出差”还是“安排行程”，会被路由到完全不同的子智能体）。因此改写时：

- **不得替换或润色用户的动作动词**。用户说“申请/报备/提交”，就必须保留“申请/报备/提交”，不能改成“安排/规划/查/订”等同义或近义动作。
- **不得凭语感补出用户没说的动作**。原问题只表达“要去某地出差”“帮我弄一下出差的事”时，禁止改写成“请帮我安排出差行程”“帮我规划一下行程”——这会把差旅申请意图带偏成行程规划。
- **动作模糊时保留模糊**。若原问题的动作本身笼统（如“帮我搞一下”“处理一下”），改写只补齐时间/地点/事由等实体，动作部分维持原样（如“请帮我处理这次出差”），由下游去判定，**不要替用户选定一个具体动作**。
- **不得增减动作数量**。单动作不得扩写成“先申请再规划”之类的复合动作；复合动作也不得合并压缩成一个。
- 高敏感动作词对照表（左侧出现时必须原样保留，**禁止**改写为右侧表达；反之亦然）：

| 原始动作表述 | 禁止改写为 |
|---|---|
| 申请出差 / 出差申请 / 出差报备 / 提审批 | 安排行程、规划行程、做方案、订机票酒店 |
| 规划行程 / 行程方案 / 安排行程 | 申请出差、提交审批 |
| 查机票 / 查酒店 / 查火车 | 订机票、预订酒店、下单 |
| 报销 / 开发票 / 贴票 | 查报销政策、问差标 |
| 取消出差 / 撤回申请 | 取消酒店、退票、改签 |
```

修改之后，同样的对话，结果就是这样的了：

![](assets/b0ad03203417.png)

可以看到，这时候agent就开始帮我们做差旅审批了。但是还有个小问题，就是他其实把意图识别成了【用户查询已有差旅申单详情/状态】，因为这个意图和发起差旅申请其实是同样都是ManageAgent，所以最终结果也是对的。

于是，我们进一步优化下L1的规则，在【用户查询已有差旅单详情/状态】这个意图增加更多约束，把 TRAVEL_ORDER_QUERY 里的裸歧义名词 差旅行程|出差安排|差旅安排 抽出来，改成必须带查询语境：

(我的|上次|最近|近期|历史|本周|本月|下周|有|查|看)[^，。；！？、]&#123;0,6&#125;(出差|差旅)(安排|行程)

并且新增负向词，如：处理 / 帮我办 / 我要办 / 安排一下等。最终就是：

```text
addRule(IntentCategory.TRAVEL_ORDER_QUERY,
        "(差旅单|出差单|差旅订单|差旅详情|差旅记录|出差记录|我的差旅|我的出差"
        + "|(我的|上次|最近|近期|历史|本周|本月|下周|有|查|看)[^，。；！？、]{0,6}(出差|差旅)(安排|行程)"
        + "|差旅单详情|出差单状态|差旅单状态|上次的?(差旅|出差)|历史(差旅|出差))",
        "提交", "发起", "提个", "新建", "报备", "取消", "规划", "报销",
        "做一份", "做个", "做一下", "出一份", "方案", "处理", "帮我办", "我要办", "安排一下");
```
