# ✅如何获取know-engine的评测集

通过前面我们介绍的方法，我们针对我们的项目获取一份用来做评测的数据集。需要注意的几个点：

1、多少数据集够用？

2、数据集怎么构成的？

3、如果是AI生成，使用什么模型？

多少数据集够用？

数据集的数量没有什么固定的要求，一般是根据不同的阶段来看，

- **流程跑通阶段（10 - 20 条）**如果你只是为了测试 Ragas 的代码能不能跑通，或者验证一下数据生成的格式对不对，生成 10 到 20 条就完全足够了。这能让你快速发现配置问题，且花费极低。
- **日常开发与快速迭代阶段（50 - 100 条）**在开发 RAG 应用时，你需要频繁地调整切分策略（chunk size）、检索参数等。准备一个包含 **50 到 100 条**高质量问答对的“黄金测试集”，既能保证评估结果有一定的统计意义，又能在几分钟内跑完评估，非常适合敏捷迭代。
- **正式上线前的最终验收（200 - 500+ 条）**如果你的知识库非常大（比如有几百上千个文档），且涉及金融、医疗等对准确率要求极高的领域，建议准备 **200 条以上**的测试集。这样可以更全面地覆盖各种边缘情况（Corner Cases）和复杂的多跳推理问题，确保系统上线后的稳定性。

在 RAG 测评中，**100 条经过人工校验的高质量问答对，远比 1000 条 AI 自动生成但未经审核的数据有价值。**

如果 AI 生成的题目本身逻辑有误，或者标准答案不准确，那么用再多的数据去评估也是没有意义的。因此，无论你生成了多少条数据，强烈建议抽出时间进行**人工抽检**，剔除掉那些质量差的样本。

数据集怎么构成的？

1、数据集的质量越高越好，所以我们应该优先选择线上的真实的对话（或者是之前的工单、常见Q&A、客诉、论坛中收集到的一些问题），从中标注出比较好的数据用来做测评。这种数据一般被称为黄金数据。

- 还有一类极具价值的数据——**系统回答失败或无法回答的案例**。在构建测试集时，不仅要收录成功的问答，还要刻意保留一部分“知识库里没有答案”的问题。这能用来测评系统的“拒答能力”
- 直接使用线上数据前，务必进行个人敏感信息的脱敏，防止在测评过程中泄露用户隐私。

2、如果线上的数据不多，那么可以基于我们标注出的真实数据做扩展，一般是针对问题做扩展，比如让LLM帮你把原始的用户改成多种问法，这样就扩展出多份数据了。

- 除了换问法，还可以专门让 LLM 模拟一些**带有错别字、口语化严重、甚至包含干扰信息**的提问。这样能更真实地考验 RAG 系统的语义检索鲁棒性。

3、纯靠AI生成，基于上篇文章中我们介绍的利用ragas基于文档生成的方式。

- 这种数据**必须有人工抽检**。

如果是AI生成，使用什么模型？

如果是需要用AI生成一些测试集的话，选择模型也不能随便，最好是选择顶尖的闭源模型，如GPT、Claude这些旗舰模型。

这些顶尖模型的逻辑推理和指令遵循能力极强，能确保生成的问题和标准答案非常严谨、高质量。

如果用开源模型，也需要用参数量大一些的，至少要在70B以上。否则会出现比较严重的幻觉。

def fetch_and_save():
    print(f"开始处理 {len(qa_pairs)} 条数据...")
    
    # 打开 CSV 文件准备写入
    with open(OUTPUT_CSV_FILE, mode='w', newline='', encoding='utf-8-sig') as csvfile:
        # 定义表头
        fieldnames = ['user_input', 'response', 'retrieved_contexts', 'reference']
        writer = csv.DictWriter(csvfile, fieldnames=fieldnames)
        
        # 写入表头
        writer.writeheader()
        
        for index, pair in enumerate(qa_pairs):
            question = pair['question']
            reference = pair['reference']
            
            try:
                # 1. 对问题进行 URL 编码，防止特殊字符导致请求失败
                encoded_question = urllib.parse.quote(question)
                url = f"{API_BASE_URL}?question={encoded_question}"
                
                # 2. 调用本地接口获取结果
                response = requests.get(url)
                response.raise_for_status()  # 如果状态码不是 200，抛出异常
                data = response.json()
                
                # 3. 提取并处理数据
                api_response_text = data.get("answer", "")
                # 将 references 列表转换为一个长字符串（用换行符分隔），方便存入 CSV 单格
                contexts_text = "\n\n".join(data.get("references", []))
                
                # 4. 写入 CSV
                writer.writerow({
                    'user_input': question,
                    'response': api_response_text,
                    'retrieved_contexts': contexts_text,
                    'reference': reference
                })
                
                print(f"[{index + 1}/{len(qa_pairs)}] 成功处理: {question}")
                
            except Exception as e:
                print(f"[{index + 1}/{len(qa_pairs)}] 处理失败: {question} -> 错误信息: {e}")

if __name__ == "__main__":
    fetch_and_save()
    print(f"\n✅ 全部处理完成！结果已保存至: {OUTPUT_CSV_FILE}")
