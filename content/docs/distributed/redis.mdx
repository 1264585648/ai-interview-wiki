# 问题

缓存和数据库怎么保持基本一致？

# 30秒回答

读多写少常用 Cache Aside：先更新数据库，再删缓存。穿透用空值或布隆过滤器，击穿用互斥重建，雪崩靠过期时间打散和限流。不要假设缓存和数据库能强一致。

# 深入理解

先删缓存再更新库，并发读可能把旧值写回缓存。先更新库再删缓存，窗口短，多数业务可接受。热点 key 要有逻辑过期或单飞重建。大 key 和热 key 分开看：一个占内存，一个打满单分片。

Redis 适合缓存、计数、分布式锁的短路径，不替代事务数据库。

# 面试追问

## 为什么不是双写？

并发写会出现后写的库、先写的缓存，时序更难讲清。删缓存让下一次读回源。

## 缓存击穿和穿透的差别？

穿透是查不存在的数据，一直打到库。击穿是热点 key 过期，大量请求同时重建。
