# 问题

RAG 解决什么问题，最小链路是什么？

# 30秒回答

模型参数记不住私有和最新知识。RAG 先把文档切块并向量化，提问时召回相关片段，再把片段和问题一起交给模型生成。关键不在“接了向量库”，而在切片、召回和引用是否可靠。

# 深入理解

离线：解析、清洗、切块、Embedding、写入向量库，并保留原文和元数据。在线：改写问题、向量召回、可选关键词召回、Rerank，最后生成并要求引用。

召回差通常是块太大、元数据没过滤、或 query 和文档用词不一致。生成编造则要限制只根据上下文回答，并让模型标出来源。

# 面试追问

## 为什么不只靠更长上下文？

长上下文贵、慢，还会稀释关键信息。检索先缩小证据范围。

## 如何评估 RAG？

分开看召回是否命中证据，以及答案是否被证据支持。不要只看最终像不像人话。
