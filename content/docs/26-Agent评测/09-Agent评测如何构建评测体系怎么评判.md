# ✅Agent评测：如何构建评测体系（怎么评判）

Agent 跑完，进入评测的核心：**让裁判对最终回复做评价。** 思路是把 Agent 的回答、评分标准，连同标准答案（如果有），一起交给一个独立的裁判，让裁判判断这份回答到底好不好。

先选裁判

裁判用什么形态，分三种情况：

- **答案静态、能提前算好（比如：DataAgent）：LLM-as-Judge，裸的大模型**
- 标准答案出题时就预执行好了，结果是静态的；
- 裁判拿报告和事实比对、打分即可，不需要现场查库，给工具反而多余。
- **有客观事实、但答案动态变化（查天气、查业务系统实时数据）：Agent-as-Judge，带工具的裁判**
- Agent-as-Judge 就是裁判本身是一个接了工具的 Agent，不是裸的大模型；
- 为什么必须接工具：这类任务出题时没法预执行标准答案，数据是活的，裁判得自己有手段把正确答案现场查出来，**现场查询事实，再拿查询结果和 Agent 的报告进行比对**。
- **主观任务（写作文、分析趋势）：LLM-as-Judge，纯 rubric 打分**
- 没有正确答案可查，Agent-as-Judge 也没意义；
- 裁判按评分标准评质量就行。

| 任务类型 | 裁判形态 | 为什么 |
| --- | --- | --- |
| **答案静态、能提前算好**（如 DataAgent） | LLM-as-Judge，裸大模型 | 标准答案可以在出题时提前执行并固化到评测数据中，裁判直接拿 Agent 报告和标准答案比对即可，不需要现场查库 |
| **有客观事实，但答案动态变化**（如查天气、查业务系统实时数据） | Agent-as-Judge，带工具 | 出题时无法提前固定标准答案，裁判必须通过工具现场获取最新事实，再与 Agent 报告进行比对 |
| **主观任务**（如写作文、分析趋势） | LLM-as-Judge，纯 rubric | 没有唯一正确答案，不需要查事实，裁判根据评分标准直接评价报告质量 |

为什么不能只判对/错

**答对 Pass、答错 Fail，这样设计起来最简单，但真正评测时很快会发现，这种方式只能判断“有没有明显答错”，却无法描述一份回答到底好不好。** 比如下面这些情况：

- **数据全查对了，却自作主张补一段没依据的分析；**
- **结论对了，但漏了用户明确要的关键指标；**
- **数字全对，但报告组织混乱，人看不懂；**
- **没明显错误，但塞了一大堆和问题无关的内容。**

这些很难简单归成“对”或“错”，主观任务更是连“对错”都定义不出来。所以评测不能只有通过率，还得有一套能描述好不好的评分机制。

怎么设计 rubric

解决办法就是引入 **Rubric（评分标准）**：不让裁判自由发挥，而是提前规定“评哪些维度、每个维度怎么看、什么情况打几分”。

先说权重怎么定：**根据你评测的 Agent 任务灵活设置，不是写死的。**

客观任务，准确性是第一要务，**正确性的权重必须给足**，比如：DataAgent 给到 40%。主观任务则反过来，没有标准答案，“正确性”退化成“事实性”（只要求不编造），权重降下来，逻辑性、完整性升上去。

比如可以按照如下的权重来设置：

| 维度 | DataAgent（客观任务） | 写作类（主观任务） |
| --- | --- | --- |
| 正确性 / 事实性 | 40% | 15% |
| 完整性 | 20% | 25% |
| 相关性 | 20% | 25% |
| 逻辑性 | 20% | 35% |

这里的数字只是示例，**重点不是固定这套权重，而是根据任务目标动态调整。**

维度也不是越多越好。这里没有单独增加“可用性”“简洁性”“可读性”等指标，是因为它们和已有维度存在明显重叠：

- **可用性**可以由正确性、完整性和相关性共同体现；
- **简洁性**可以并入相关性，看是否存在大量无关内容；
- **可读性**可以并入逻辑性，看报告组织是否清晰。

**维度太多，反而会增加裁判的判断负担，降低评分稳定性。** 对 DataAgent 这种数据分析任务，基本上四个维度就足够了。

| 维度 | 权重 | 评什么 |
| --- | --- | --- |
| 正确性 | 40% | 数值和结论对不对，有没有编造 |
| 完整性 | 20% | 该答的要点覆盖了没 |
| 相关性 | 20% | 有没有跑题、乱补充无关分析 |
| 逻辑性 | 20% | 结论组织、推理是否清晰 |

设定分数档位

确定维度后，还要解决一个问题：裁判到底打多少分。

不能让裁判自由发挥，直接给出“83 分”这种连续分。连续分看起来精细，实际上容易产生随机波动：同一份报告，换一次评测可能就从 78 分变成 87 分。更稳定的做法是使用**有明确锚点的档位分**，例如统一采用 5 分制，让裁判根据描述对号入座。

锚点怎么定，同样分情况：**客观任务的档位，锚定“和标准答案的偏差程度”；主观任务的档位，锚定“质量水平的描述”。** 不管哪种，每一档都得有明确标准，杜绝自由发挥。

拿客观任务 DataAgent 举例：

| 分数 | 标准 |
| --- | --- |
| 5 分 | 关键数据和结论全部正确，没有编造 |
| 4 分 | 核心结果正确，仅非常轻微的非关键偏差 |
| 3 分 | 主体正确，但次要数据或结论有偏差 |
| 2 分 | 较明显错误，但部分核心结果仍正确 |
| 1 分 | 关键数据或结论错误 |
| 0 分 | 明显编造，用了标准事实里不存在的数据 |

其中**编造要单独拎出来记 0 分**，因为它性质最严重：**算错是能力问题，编造是可信度问题**。一个敢编数据的 Agent，要么是模型能力不行、没走工具，要么是上下文管理混乱、没按流程来，不管哪种，都比算错更值得警惕。

主观任务的维度也是同样的分档思路，只是锚点换成质量描述。比如逻辑性：5 分是论证严密、条理清晰；3 分是整体连贯但局部跳跃；1 分是想到哪写到哪。

评测结果汇总

裁判完成评分后，还需要把结果汇总成最终指标。这里同样需要分情况讨论，比如：**客观任务需要出两个数，主观任务只需一个。**

**通过率（通过/不通过）**：只有客观任务有，这是硬性的。对 DataAgent，正确性就是底线：核心数据错、核心结论错、明显编造，直接判不通过。例如某道题 5 遍中通过 4 遍，那么这道题的通过率就是 80%。**通过率是客观任务的硬指标。** 而主观任务没有对错，可以设个及格线（比如 3 分）当软门槛，也可以不设。

**质量分**：两种任务都有，过了门槛再算。总分 = 各维度分数 × 权重：

总分 = 正确性 × 40% + 完整性 × 20% + 相关性 × 20% + 逻辑性 × 20%

比如正确性 5、完整性 3、相关性 5、逻辑性 4，总分就是 5×0.4 + 3×0.2 + 5×0.2 + 4×0.2 = **4.4 分**。

有人可能会问：不是说不打连续分吗，怎么又出来 4.4 这种小数？**档位分约束的是裁判这个环节**：裁判只打每个维度的整数档，对号入座；加权求和、跨遍平均都是程序算的，不经过裁判。

跑完主要就看下面三个指标：

| 指标 | 怎么算 | 看什么 |
| --- | --- | --- |
| 通过率 | 先算单题（5 遍过几遍），再跨题平均 | 对不对 |
| 平均分 | 各维度加权后，再跨遍、跨题平均 | 好不好 |
| 全对率 | 5/5 全对的题数 ÷ 总题数 | 稳不稳 |

为什么光看通过率还不够。比如两个 Agent：

- Agent A：12 题全对、8 题全错；
- Agent B：20 题全部 3/5。

两者平均通过率可能都是 60%，但 A 是“一半稳定一半全挂”，B 是“每道题都像在掷硬币”。所以除了通过率，还得看稳定性，全对率就是干这个的。

**通过率先算单题再跨题平均，而不是总通过次数除以总运行次数。两者在每道题遍数一样时结果相同，但一旦给个别题加跑，后者会让跑得多的题权重变大，一道题就能影响总分，所以固定先单题再平均。**

小结

裁判分三种形态：**答案静态、能提前算好的用 LLM-as-Judge，直接比对预执行的标准答案；事实动态、没法提前算的用 Agent-as-Judge，裁判带工具现场查证；主观任务则使用纯 rubric，只评质量。**

只判对错不够，要用 rubric 打分：四个维度，权重按任务灵活配，客观任务正确性给足（DataAgent 40%），主观任务正确性退化成事实性、逻辑性升权。裁判只打**有锚点的档位分**，客观任务锚定偏差程度、主观任务锚定质量描述，杜绝“我觉得 83 分”这种自由发挥；**编造单独记 0 分**，算错是能力问题，编造是可信度问题。

结果汇总：客观任务两个数（通过/不通过 + 质量分），主观任务一个质量分；整体看**通过率、平均分、全对率**三个指标，光看通过率分不清“一半稳定一半全挂”和“每道题掷硬币”。
